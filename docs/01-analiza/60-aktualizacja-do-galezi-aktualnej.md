### 2.3 Tank — pseudokod „dowódca i awans”

`size`, `fish`, `temp`, `ph` stosują porządek pasm od najmniejszej lub najniższej wartości. Typ jest bramką K1. Ranking ważony następuje po bramkach. `aquasmart_v103/includes/class-aqs-tank-match.php:20–34,44–85`

```text
evaluate(tank, fauna):
    size = trim_or_null(tank.size_band)
    jeśli size nie należy do SIZE_ORDER:
        zwróć ok=false, "Brak wielkości akwarium w zbiorniku."

    fish = trim_or_null(tank.fish_size_band)
    fish_source = user
    jeśli fish jest null:
        fish = FISH_ORDER[index(size)]
        fish_source = derived

    temp = trim_or_null(tank.temp_band)
    ph = trim_or_null(tank.ph_band)
    type = trim_or_null(tank.type_label)
    oceniane = występujące wartości z [size, fish, temp, ph] w tej kolejności
    wagi = przypisz ocenianym kolejne wartości z [4, 3, 2, 1]

    ranked = []
    excluded = 0
    no_data = 0
    dla rekordu w fauna:
        jeśli podano type i TypAkwarium rozdzielone po ";" nie zawiera type ani "Wszystkie":
            excluded += 1
            pomiń rekord

        jeśli oba indeksy są znane i index(rekord.Wielkość) - index(size) >= 3:
            excluded += 1
            pomiń rekord

        scores = {}
        size: 3 dla "Wszystkie" albo różnicy 0
              2 dla index(size) - index(WielkośćAkwarium) = +1
              1 dla różnicy -1, 0 dla pozostałych znanych różnic
              null dla pustej lub nierozpoznanej etykiety

        fish i temp: 3 za różnicę bezwzględną 0, 1 za różnicę 1, 0 dalej
                     null, gdy etykieta wejścia lub rekordu jest nierozpoznana

        ph: rozdziel wartości rekordu po ";"
            3, jeśli którakolwiek jest równa wejściu
            1, jeśli którakolwiek jest sąsiednia
            0 w pozostałych przypadkach, gdy lista jest niepusta, a wejście znane
            null dla pustej listy lub nieznanego wejścia

        zachowaj w scores tylko oceniane kryteria z wynikiem różnym od null
        W = suma wag kryteriów zachowanych w scores
        jeśli W = 0:
            no_data += 1
            pomiń rekord

        points = suma(score[k] * waga[k])
        percent = round(100 * points / (3 * W))
        dopisz wynik do ranked

    jeśli ranked jest puste:
        zwróć ok=false, excluded, no_data

    sortuj malejąco po:
        [percent, score.size, score.fish, score.temp, score.ph]
        brak pojedynczego score traktuj jako -1
    ostatni klucz: strcasecmp(nazwa_łacińska), rosnąco
    zwróć pierwszy rekord jako winner, pozostałe jako others
```

- Brak temperatury promuje pH z wagi `1` na `2`. Typowe maksima to **30 / 27 / 21** odpowiednio dla czterech, trzech i dwóch kryteriów. Brak pola u gatunku zmniejsza mianownik tego gatunku, zachowując przypisane wagi pozostałych pól. `aquasmart_v103/includes/class-aqs-tank-match.php:50–69,87–134`
- Ważna różnica danych: `score_size()` oczekuje pojedynczej etykiety albo dokładnie `Wszystkie`. Wielowartościowe `WielkośćAkwarium` może zatem usunąć kryterium o wadze `4` i dać rekordowi 100% z mianownika **18**. Gdy nazwy łacińskie i cały klucz są równe, komparator nie dodaje ID jako ostatniego klucza. `aquasmart_v103/includes/class-aqs-tank-match.php:113–134,161–173,223–232` · `aquasmart_v103/data/baza_fauna_end1.txt.php:40–41`
- Granica `>=3` odrzuca `Duża` i `B. duża` przy Nano oraz `B. duża` przy Małym. Jest niezależna od preferowanego rozmiaru ryby. Wynik `0` na jednym kryterium sam w sobie nie odrzuca rekordu. `aquasmart_v103/includes/class-aqs-tank-match.php:21–34,75–118,206–211`

### 3.1 Format, ochrona i wybór źródła

- `baza_*.txt.php` ma strażnika `<?php exit; ?>`, potem nagłówek TSV i rekordy UTF-8. Loader preferuje wariant z `.php`, obsługuje stary plik bez sufiksu, odcina strażnika i BOM, czyta z `php://temp` przez `fgetcsv` z tabulatorem, przycina wartości i pomija rekordy bez `id`. Aktywacja lub zmiana wersji przełącza na `bundled`. - Ochrona nagłówkiem działa przy wykonaniu pliku przez PHP. Importowana kopia bez strażnika korzysta z ochrony katalogu. ### 5.2 Przepływ zamówienia i gwarancje

1. **Oferty.** Placówka po weryfikacji może dodawać pozycje katalogowe z czterech obszarów. `inny_towar` pozostaje stałą dla starszych danych. Obecna walidacja wymaga `0 < cena ≤ 100 000`, puli **0–1000**, obu dat i wariantu do **100 znaków**. Moderacja ofert domyślnie `0`. `aquasmart-shops/includes/class-aqss-offers.php:14–24,40–53,185–265` · `aquasmart-shops/includes/class-aqss-core.php:16–28`
2. **Koszyk klienta.** Zalogowany dodaje lub zmienia `offer_id => qty`, maks. **50 szt.** w pozycji. Walidacja odrzuca własną placówkę i przekroczenie aktualnej puli. Przy wysłaniu `checkout_all()` dzieli po sklepie. `checkout()` tworzy losowy 16-znakowy klucz `basket`, po czym zapisuje pozycje osobno. `aquasmart-shops/includes/class-aqss-cart.php:15–98,104–184` · `aquasmart-shops/includes/class-aqss-requests.php:13–15`
3. **Złożenie.** `create()` zapisuje pozycję `NOWE`, `number=NULL`, snapshot nazwy/ceny i ilość. Domyślny dzienny limit **5** liczy wiersze zgłoszeń, czyli pozycje. Samo zgłoszenie nie rezerwuje puli. Działa częściowy sukces: wysłane pozycje wypadają z koszyka, błędne zostają, a wynik może zgłosić sukces całego sklepu. `aquasmart-shops/includes/class-aqss-requests.php:38–108` · `aquasmart-shops/includes/class-aqss-cart.php:136–184` · `aquasmart-shops/includes/class-aqss-core.php:17–24`
4. **Zatwierdzenie.** `AQSS_Basket::approve()` sprawdza członkostwo/cap `requests`, wykonuje `START TRANSACTION`, blokuje `basket + shop_id` przez `FOR UPDATE` i wymaga wszystkich pozycji w `NOWE`. Sumuje zapotrzebowanie per oferta, warunkowo odejmuje z `pool_qty` i dodaje do `pool_reserved`. Pozycje przechodzą do `POTWIERDZONE`, `qty_confirmed=qty_requested`, powstaje historia i próba nadania numeru. Niewystarczająca pula powoduje rollback. `aquasmart-shops/includes/class-aqss-basket.php:30–114`
5. **Odrzucenie.** `reject()` blokuje podkoszyk tak samo. Powody `brak_aktualnej_oferty` i `inne`; `inne` wymaga opisu. Wszystkie pozycje dostają `ODRZUCONE`, kod i historię, a po commicie klient otrzymuje jeden e-mail z listą pozycji. Odrzucony podkoszyk także próbuje otrzymać EAN-13. `aquasmart-shops/includes/class-aqss-basket.php:18–24,124–232`
6. **EAN-13.** `2` + **4 cyfry ID placówki** z zakresu `1–9999` + **7 cyfr globalnego licznika** `1–9 999 999` + cyfra kontrolna z wagami `1/3`. Licznik to opcja `aqss_order_seq`. Przed numerem UI pokazuje „w toku”. Mapa przewiduje ten sam numer jako numer zamówienia, kod kreskowy i tytuł przelewu. `aquasmart-shops/includes/class-aqss-numbering.php:18–81` · `aquasmart-shops/includes/class-aqss-requests.php:17–20,506–529` · `docs/mapa-funkcjonalnosci.md:227–232`
7. **Ponowienie decyzji.** Druga próba trafia na stan inny niż `NOWE` i kończy się `PODKOSZYK_ZAMKNIETY`. To ochrona efektu decyzji, bez replay poprzedniej odpowiedzi i bez osobnego klucza żądania. Checkout, który tworzy losowy klucz dla każdego wykonania, nie ma tej samej gwarancji. `aquasmart-shops/includes/class-aqss-basket.php:44–61,148–164` · `aquasmart-shops/includes/class-aqss-cart.php:154–184`
